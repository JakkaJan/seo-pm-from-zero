# PRD: SEO Site Health Monitor (SSHM)
## Автоматизированная система мониторинга состояния сайтов клиентов

### 2. Проблема (Problem Statement)

Веб-студия DELTA обслуживает 80+ клиентов. Аудиты сайтов проводятся вручную:
- 1 аудит = 2–4 часа специалиста
- Частота: раз в 2–3 месяца (вместо ежемесячной)
- 30% клиентов на "Базовом" пакете вообще не получают регулярный мониторинг
- Критические ошибки (битые ссылки, отсутствие meta, медленная загрузка) обнаруживаются с опозданием на 4–8 недель

**Бизнес-риск:** клиенты уходят к конкурентам из-за проседания позиций, которые мы не заметили вовремя.

### 3. Цель (Goal)

Автоматизировать ежемесячный аудит технического состояния сайтов клиентов, сократив время ручной работы на 70% и обеспечив 100% охват клиентов.

### 4. Успех (Success Metrics)

| Метрика | Базовое значение | Целевое значение | Дата измерения |
|---------|-----------------|------------------|----------------|
| Время на аудит 1 сайта | 180 мин (ручной) | 15 мин (авто + ручная проверка) | Через 1 месяц |
| Охват клиентов аудитом | 45% (только Премиум) | 100% | Через 2 месяца |
| Среднее время обнаружения критической ошибки | 6 недель | 7 дней | Через 3 месяца |
| Retention клиентов на SEO-пакетах | 78% | 90% | Через 6 месяцев |

### 5. Функциональные требования (FR)

#### FR-001: Автоматический сбор метрик
Система должна сканировать сайт клиента и собирать:
- HTTP-статус главной страницы
- Title, Description, H1 (наличие, длина)
- Время ответа сервера (TTFB)
- Количество битых ссылок (на уровне главной + 2 уровня вложенности)
- Наличие SSL-сертификата
- Размер HTML-страницы (KB)

#### FR-002: Приоритизация клиентов
Система должна автоматически выставлять приоритет аудита:
- **P0 (Критический):** клиенты "Премиум" + сайт с ошибками на прошлом аудите
- **P1 (Высокий):** клиенты "Стандарт" + запуск < 6 месяцев назад
- **P2 (Средний):** клиенты "Базовый" + стабильные метрики
- **P3 (Низкий):** клиенты без активного SEO-пакета

#### FR-003: Генерация отчёта
Система должна генерировать PDF/Excel отчёт с:
- Таблицей метрик по всем клиентам
- Цветовой индикацией (зелёный / жёлтый / красный)
- Топ-3 проблемы с рекомендациями
- Динамикой по сравнению с прошлым аудитом

#### FR-004: Уведомления
Система должна отправлять email-уведомление аккаунт-менеджеру, если:
- SEO-score упал более чем на 10 пунктов
- Обнаружены битые ссылки (≥3)
- Время загрузки превысило 3 секунды

#### FR-005: API для интеграции
Система должна предоставлять JSON API для выгрузки данных в внутренний дашборд студии.

### 6. Нефункциональные требования (NFR)

| ID | Требование | Значение |
|----|-----------|----------|
| NFR-001 | Язык разработки | Python 3.10+ |
| NFR-002 | Хранение данных | SQLite (MVP) / PostgreSQL (production) |
| NFR-003 | Формат отчётов | CSV + JSON |
| NFR-004 | Время выполнения сканирования 1 сайта | < 30 секунд |
| NFR-005 | Логирование | Все операции записываются в файл logs/audit.log |
| NFR-006 | Конфигурация | Через config.yaml (URL-ы, пороги, email-ы) |

### 7. Ограничения MVP

- Сканирование только главной страницы + sitemap.xml (без полного краулинга)
- Email-уведомления — через консольный вывод (без SMTP-интеграции в MVP)
- База данных — SQLite, одна таблица `audits`
- Отчёт — CSV + консольная таблица (без PDF в MVP)
